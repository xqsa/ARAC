## 一、研究背景与算法框架

**ARAC-OC**：面向变量重叠的大规模黑盒全局优化的在线组合协调
框架（1000 维 AOB 基准，3M FE 预算）。

```text
Phase-I 身份盲重叠证据发现（soft-RDDSM，180k FE）
    ↓ checkpoint（块结构 + 关系 + incumbent）
GCB 协调器在线调度（不预先固定动作）
    ├─ 顺序上下文探针（各 episode 边际贡献）
    ├─ 阶段感知：ticket / challenger / escalation / exploit
    ├─ 全局 strict-best materiality（私有改善不驱动调度）
    └─ scope 引导（证据块序）
四个搜索 episode：CTP（覆盖修复）/ GSS(gcb)（图扫掠）/
    SMP（记忆局部）/ AOR（fresh-by-design 全局校正）
全局 strict-best archive + handoff 接力（AOR 只收基线不收状态）
逐 FE 收据 / 13 项调度审计 / 版本隔离产物
```

**五个创新点**：在线发现当前有效动作；阶段感知调度（不因短窗
收益淘汰慢热动作）；全局 materiality 过滤假粘性；跨 episode 状态
接力；组合收益目标（同 checkpoint 同预算超过全部 standalone）。

**SOTA 差异化**（`docs/sota-oracle-confirmation.md`）：HCC-ES
（GECCO 2025）的分解直接读 AOB 构造文件（oracle），零黑盒检测；
ARAC-OC 无先验工作。HCC 24 函数参照值已提取固化于
`references/hcc_aob24_reference.json`。

**完成标准**（用户定义）：同 checkpoint 同预算不明显劣于历史最佳
派发；R2 型晚熟 AOR 显现后获 exploit；S5 型长程 CTP 获连续开发窗；
≥1 case 严格胜全部 standalone + ≥2 material episode；24×5 完整
对比 HCC。

## 二、创新想法的演化（重要：设计取向曾反转）

v4.0-v4.2 试图用**反粘滞交错**（max-2 连续 exploit 上限）保护
探索——结果每修一个 case 破另一个（R2 需要打断零增益垄断，
S5 需要保护 material 长跑，两者共享同一批预算）。

v4.3 起取向反转为 **v3 获胜核心 + 保留节奏保护**：material
leader 连续跑 + 停滞换道 + 探针/票据速率永不加冕 leadership +
保留节奏（每 2×segment_fes exploitation 强制开一个开发事件）。
v4.4 加健康度条件公平（MATERIAL_RUN/DISCOVERY_RUN 状态机）。

**用户实现的 v5/v5.1**（当前候选，代码在 `episodes.py` 尾部）：
- **HPR（horizon 保护）**：material leader 拥有 protected_runway
  （保留节奏可入但不打断）；leader 停滞时 horizon 梯档给未穿越
  臂供血；
- **adaptive_lock（v5.1 独有）**：material ticket 完成后立即插入
  一次真实验证 exploit——真引导立即兑现，假引导一窗识破；
- 配置旗标：`horizon_protected=True, adaptive_exploration=True`。

## 五、遇到的问题（开放与已解决）

### 已解决（本轮，要点）

1. v4.0-v4.2 反粘滞交错的结构性失败（跷跷板）→ v4.3 取向反转；
2. 探针速率加冕（20k 小样本大速率永不老化）→ leadership 只认
   exploit 样本速率；
3. 采样公平打断 material 长跑 → 健康度门控（MATERIAL_RUN/
   DISCOVERY_RUN）；
4. 零增益垄断（ctp 烧 1.24M 无对手）→ 采样公平下限（仅在
   DISCOVERY 态触发）；
5. 救援通道被健康 leader 扼流 → 保留节奏（cadence 与 leader
   健康解耦）；
6. 四个 overflow cell（R2/R6 ctp/gcb）与 Gate 50 不逐位 →
   根因 = sigma 安全修复晚于 Gate 50；判定锚已切换到当前树
   全预算值（`overflow_reference.json`，三好一差 0.08% 如实记录）；
7. 性能：E 核调度 + 带宽争用 + 僵尸进程 + 管道事故 → P 核钉定
   + 2.4× vendor 提速 + 复用体系（教训：长跑后台命令禁套
   head/grep 管道；杀进程后必须清孤儿 worker）。

### 开放

1. **S5 的 exploration tax 定价**：ctp standalone 全长打磨需
   ~2.8M，组合最多给 ~1.9M（还要养三个弟兄）——2.9× 中位数是
   当前税率的价；plateau 释放能救灾难 seed，税本身是结构性的；
2. R6 的 1.05 边缘（机制对、差一点）；
3. R2 standalone 侧方差大（各 seed 最优臂不同）——中位数判据
   对它偏严，可能需要多 seed 或换判据口径讨论；
4. AOR contextual horizon ≠ standalone（51-0 已声明局限，
   v5.1 的 horizon 梯档是补偿机制）。
